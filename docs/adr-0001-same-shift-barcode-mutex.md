# ADR-0001：同班次同条码再扫口径——互斥单行臂

## 背景

同一分拣班内，物流件条码被二次过机时，装载回执、扫描册、待路由桶、裁决入口、口门页、
总览、审计可能各说各话：重复提示与实际装载不一致；并发双扫的半截事务可能双双落行，
破坏条码唯一。需求要求在两种可行架构中全局只贯彻一种。

## 决策

采用**「同班次同条码互斥单行」臂**，全局唯一口径：

1. 同一班次（`shift_id`）内同一 `barcode` 至多存在一行 `scans` 记录，由数据库唯一约束
   `UNIQUE(shift_id, barcode)` 兜底，应用层预检查只是优化，不作为正确性来源。
2. 同班次同条码的第二次（及之后每次）过机装载：**整笔写失败**——
   - 不新增 `scans` 行；
   - 不修改既有行的任何状态（`status/chute_id/bag_id/...` 原样保留）；
   - 返回 HTTP 409，结构化回执带拒因码 `duplicate_in_shift` 与既有行引用。
3. 拒扫本身必须可重放：拒绝事件落入 `audit_events`（`action='再扫拒收'`），
   通过独立保存点（SAVEPOINT）提交，不随失败的业务写回滚。
4. 所有读路径（扫描册、待路由桶、裁决入口、口门页、总览、班次对账）只统计真实落库的
   单行；失败的再扫不产生行，因此天然不进任何桶，禁止把拒扫算进待路由。
5. 并发双扫：写连接开启 WAL + busy_timeout + `BEGIN IMMEDIATE`，由 SQLite 唯一索引仲裁，
   恰好一个事务成功，另一个收到 `IntegrityError` 并转为 409；半截回滚后同码行数仍为 1，
   且该结果可由扫描册行数与审计重放。
6. 条码在 `scans` 内的班内次序即行 `id`（单行臂下同班次同码只有一行，不存在同码多行）。

## 不采用的另一种架构（另开行臂 / 互斥缺口账臂）

允许同班次同条码另落一行并靠次序号区分；或允许先落一侧回执、双行/无行时只写
「互斥缺口」并冻结成功宣称。两路均被否决：

- 另开行臂会使一件实物在扫描册/对账中被计为两件，且全链路（入袋、回流、封袋、
  口门容量）均以 scan 行为单位，多行臂要求这些环节全部具备同码归并语义，当前域模型不具备。
- 缺口账臂允许「绿灯与互斥证据暂时撕裂、事后补账」，与「任一成功灯必须能由同班次
  同条码至多一行正式未结 ∪ 扫描册 ∪ 占用态同命运重放」直接冲突；缺口字段本身会成为
  第二条真相来源，调度仍可能把两笔当已装载。

**全局不得混用另开行臂/缺口账臂的任何语义**：不得出现同班次同码两行；不得出现仅在
展示层合并的补偿逻辑；不得存在独立于真实行的占用灯/成功宣称/缺口设置项。
本臂下「假双破如何收口」的唯一口径：双破即整笔回滚后到者并回退幽灵行，由库级唯一
索引 + 同事务写闸保证，而不是记账冻结。

## 单一证据面：互斥探针

`app/services/mutex_probe.py` 是占用灯/对账的唯一证据面，只从真实 `scans` 行与同事务
`audit_events` 派生，经 `GET /api/互斥探针` 暴露，并被总览（`/总览`）与班次对账
（`/班次/对账`）共用。任一计数非零即互斥撕裂：

- 同码多行数 / 皮带（分拣线）双挂数；
- 无行成功灯数（审计有「过机装载」绿灯但引用行不存在）；
- 灯册不符数（按条码维度，册行数与成功灯数必须各为 1）；
- 桶册一致（调度各状态桶之和 = 扫描册行数）、非正状态行数；
- 占用灯（每码占用行数恒为 1）。

历史脏库的第二路残留（`surface_*`、`mutex_twin:*`、`mutex_surface:*` 设置键与
`kind='表面'` 的「成功宣称」假流水）在 `init_db()` 内由 `_purge_surface_residue` 清除；
同码多行由 `_migrate_scan_uniqueness` 归并为单行，归并保留行缺成功灯时补一盏可重放的
「过机装载」灯，收口后灯册恢复 1:1。

## 范围

仅覆盖**同班次同条码**再扫。跨班次同条码不受此约束（唯一索引含 `shift_id`），
跨班次策略另立需求。

## 联动面（必须同刷）

装载写口（唯一主体 `scans.load_scan`，两路装载口共用）、条码唯一谓词、班次、
扫描册（GET /扫描）、待路由桶、裁决入口（POST /扫描/{id}/路由）、口门页、回流、
封袋、总览、互斥探针（GET /互斥探针）、审计（含条码重放入口）、班次对账。
